# 1. Record architecture decisions

Date: 2026-10-22

## Status

Accepted

## Context

We need to record key architectural, infrastructural, and design decisions made throughout this capstone project so that examiners, reviewers, and developers understand why specific technical choices were made.

## Decision

We will use Architecture Decision Records (ADRs) structured with:
- Title
- Date and Status
- Context
- Decision
- Consequences

ADRs will be stored in `docs/adr/` as version-controlled Markdown documents.

## Consequences

- Architectural choices are transparent, reviewable, and defensible during project examination.
- Technical decisions cannot be changed without documenting the rationale in an ADR.
