## Goal
A safe, testable LLM layer: provider abstraction (fake / cache-only / live Gemini), a hard daily request budget and throttle (the real free quota is tiny), a Mongo cache, a small knowledge base (KB) with retrieval, per-error explanations and a session narrative, deterministic fallbacks, and minimal UI panels. **Tests never call the real API.**

## The quota reality (drives every decision)
The operator's key has, for `gemini-3.8-flash`: **5 requests/minute, 250k tokens/minute, 20 requests/day**. Google documents that limits are per project (not per key), per model, and that the daily quota resets at midnight Pacific time. 20 calls/day must be shared by this task's smoke test, explanations, narratives and the image-analysis and question-generation batches of T08. Therefore:
- Every live call is counted in Mongo BEFORE it is sent; a daily budget (`LLM_DAILY_REQUEST_BUDGET`, default 16 = 20 minus a reserve of 4) stops live calls; after that the system behaves like `cache-only` until the next Pacific day.
- Calls are spaced by at least `LLM_MIN_INTERVAL_MS` (default 13000) across processes (API server and scripts) using a stored `lastCallAt`.
- Resident-facing endpoints almost never call Gemini: explanations are PRE-GENERATED by a script and served from cache; only the narrative may trigger one live call (cache miss + live mode + budget left), otherwise a deterministic fallback is returned.
- The operator should not use the same model in AI Studio chat on days when batch scripts run (it probably shares the project quota — verify on `aistudio.google.com/rate-limit`).

## Binding decisions
| Topic | Decision |
|---|---|
| Modes | `LLM_MODE=live\|cache-only\|fake`; default `cache-only` (never hits the network by accident); ALL tests use `fake`; `LLM_ENABLED=false` -> fallbacks only. `live` without `GEMINI_API_KEY` -> startup error with a clear message. |
| New env | `LLM_MODE`, `LLM_ENABLED`, `GEMINI_API_KEY`, `GEMINI_MODEL=gemini-3.8-flash`, `LLM_DAILY_REQUEST_BUDGET=16`, `LLM_MIN_INTERVAL_MS=13000`, `LLM_TIMEOUT_MS=60000`, `LLM_RATE_LIMIT_PER_USER_PER_HOUR=30`. Add to `.env.example`, `env.js` (Zod) and `apps/api/README.md`. |
| Budget day | The "day" is the calendar date in `America/Los_Angeles` (`Intl.DateTimeFormat('en-CA', { timeZone })`). Collection `llm_usage`: `{ day (unique), count, lastCallAt, exhausted }`. Reserve with an atomic `findOneAndUpdate` (+ upsert, retry once on duplicate-key). Count every attempt, including retries and failures; never refund. |
| 429 handling | On 429: wait 65 s and retry ONCE; a second 429 sets `exhausted = true` for that day and the call fails (service then falls back). No other retries on 429. |
| Output retries | Invalid JSON/schema: at most 1 retry (it costs quota); then fallback. |
| Explanation key | Explanations are keyed by `(lang, trueClass, userAnswer)` — 6 wrong-answer pairs — NOT by image or bucket (deviation from the skill; reason: 6 cached items instead of hundreds, so the demo works fully offline). One pre-generation call (<= 10 items) per language. |
| Who may trigger live | `explanations` endpoint: cache or fallback only, never live. `report-narrative`: cache -> live (if mode live and budget left) -> fallback. |
| Narrative numbers | The input JSON carries ONLY integers for percentages (rounded in code, field names end with `Percent`) and raw counts. The output guard (below) compares against them. |
| Output guard | Reject (-> fallback) any text containing `%`, or any digit sequence not present among the numbers in the input. Normalize Persian/Arabic-Indic digits to ASCII before comparing. Arrays of strings (not numbered lists) avoid false positives. |
| Privacy | Prompts contain no user id/email/name; the session is labelled `S{index}`. A test scans the built prompt for the user's id and email. No images in this task. |
| Disclaimer | Every LLM panel shows the i18n text `disclaimer.educational` (educational use, not diagnosis). |
| KB | Markdown files with front-matter `reviewed: false`; content is limited to the seed facts below. Do NOT invent references; leave `sources: []` (the instructor/clinician adds them when reviewing). UI shows a «پیش‌نویس» badge while `reviewed` is false. |
| Cache export | Pair explanations are `portable`; `npm run llm:cache:export` writes `apps/api/seed/llm-cache.portable.json` (committed, text only) and `llm:cache:import` upserts it, so a fresh database can run demos offline. Narratives are not exported. |

## KB seed facts (the ONLY medical statements the agent may use; translate to Persian, keep them short)
- `covid19`: typical chest X-ray findings are bilateral airspace opacities, often peripheral and lower-zone predominant; ground-glass opacity and/or consolidation; pleural effusion and lymph node enlargement are uncommon; the X-ray can be normal early and is less sensitive than CT; findings are nonspecific, diagnosis depends on laboratory testing and clinical context.
- `pneumonia`: bacterial pneumonia typically shows focal lobar or segmental consolidation with air bronchograms and may have a parapneumonic effusion; viral or atypical pneumonia more often shows bilateral perihilar/peribronchial thickening, an interstitial pattern, patchy opacities and, especially in children, hyperinflation. In this project the class is not divided into subtypes.
- `normal`: clear lung fields, sharp costophrenic angles, normal heart size and mediastinal contours, no focal opacity, no effusion.
- `covid19-vs-pneumonia`: bilateral peripheral ground-glass opacities in lower zones favor COVID-19; focal lobar consolidation with air bronchograms, often unilateral, favors bacterial pneumonia; the overlap is large (viral pneumonia and COVID-19 can look alike) and the chest X-ray alone cannot reliably separate them.
- `pneumonia-vs-normal`: mild or early pneumonia can be subtle; check behind the heart, the perihilar regions, the area behind the diaphragm and the costophrenic angles; rotation, poor inspiration and technique can mimic opacities.
- `covid19-vs-normal`: early COVID-19 can have a normal chest X-ray; look for subtle peripheral or basal haziness; a normal X-ray does not exclude COVID-19.
File names: `apps/api/src/modules/llm/kb/<slug>.md`; front-matter keys: `slug`, `reviewed: false`, `classes: [...]`, `tags: [...]`, `sources: []`.

## Endpoints (resident, cookie required, own finished sessions only; another user's session -> 404, unfinished -> 409 `SESSION_NOT_FINISHED`)
| Method + path | Behavior |
|---|---|
| `POST /api/sessions/:id/explanations` | body `{ lang }`; the server takes the WRONG ANSWERED questions of the session, groups by `(trueClass, userAnswer)`, returns one item per wrong question (`no`, the pair item) from cache or fallback; `source` is `cache` or `fallback` |
| `POST /api/sessions/:id/report-narrative` | body `{ lang }`; builds the stats input from the stored metrics and `buildProgress` (trend, top confusions, current weights); cache -> live -> fallback; per-user rate limit |
| `GET /api/admin/llm/status` | instructor: mode, model, today's `count`/`budget`/`exhausted`, cache entry counts |
Fallbacks: explanation fallback is built from the KB pair file (first sentences) — deterministic; narrative fallback is a template that states the numbers computed by code (overall accuracy, weakest class, top confusion, trend up/down). Both exist in fa and en.

## Tests (Vitest + supertest; `fake` provider only)
1. Guard: `%` rejected; unknown number rejected; Persian digits normalized; numbers from input accepted.
2. Schemas: length limits, exactly 3 recommendations.
3. Provider contract with the fake provider; invalid JSON -> one retry -> fallback; the retry is counted in usage.
4. Budget: reserve increments atomically (two parallel reserves at count = budget-1 -> exactly one succeeds); exhausted flag -> no provider call; Pacific-day rollover (inject a clock); throttle waits at least the interval (fake timers); 429 -> one retry -> then `exhausted`.
5. `cache-only` and `LLM_ENABLED=false` never call the provider (spy); cache hit vs miss; prompt version change misses.
6. Retrieval: query (covid19, pneumonia) returns the pair file first, max 3 chunks.
7. Endpoints: explanations for a finished session with known wrong answers -> correct pairs, `source` fallback then `cache` after seeding the cache; unfinished -> 409; other user -> 404; narrative live path with fake provider writes cache and consumes 1 budget; second call is a cache hit; rate limit -> 429 `RATE_LIMITED`.
8. Privacy: the prompt text for narrative contains neither the user id nor the email.
9. Cache export/import round trip on a temp database.
10. Real-API smoke script exists but is NOT in CI.
